Bottom line

Yes for the core — not a turnkey full submission. From captured eCRF data, one derive run produces a genuine, reviewable CDISC package: ten SDTM domains, the subject-level (ADSL) and time-to-event (ADTTE) ADaM datasets, a Define-XML v2.1 metadata file, SAS Transport (XPT v5) datasets, a starter table/figure set, and an ICH E3 clinical study report — assembled into one submission-bundle ZIP.

What it is not yet: a complete FDA/EMA eCTD Module 5 package. Several standard SDTM & ADaM datasets, the reviewer guides (SDRG / ADRG / annotated CRF), and — critically — MedDRA / WHODrug medical coding are outstanding. Coding is license-gated, not an engineering gap.

  • Produced — derived & in the bundle
  • Partial — produced with a documented caveat
  • Not yet — buildable, on the backlog
  • Blocked — external license or multi-quarter build

How to generate it: derive with POST /api/edc/deployments/{id}/cdisc/derive, then pull the submission-bundle ZIP. Survival TLFs render via /cdisc/survival/render.

Reading the gaps: most Not-yet rows are backlog-buildable (the data usually already exists in the platform); the two hard limits are MedDRA/WHODrug (paid license) and the reviewer-guide/eCTD packaging that is inherently an operator step.

Assessment reflects the cdisc/ package on branch feat/backlog-quick-wins. Status is coverage-of-standard, not a regulatory clearance.
